## Bug Tracking Tool & Workflow: **Atlassian Jira**

### 1. Selected Bug Tracking Tool
- **Tool:** **Atlassian Jira** (`Project Key: SAS`, `Issue Type: Bug`)
- **Automated Test Framework:** `pytest` (`test_logic.py`, configured in `requirements.txt`)

### 2. Jira Defect Lifecycle Workflow
Every failed Test Case (`TC01`–`TC40`) or runtime anomaly follows the 4-stage Jira workflow implemented in both the app (`admin.html` → `/api/bugs`) and Jira Board:

`[To Do]` → `[In Progress]` → `[In Review]` → `[Done]`

1. **To Do (New / Open):** Tester/Admin logs defect with linked `Test Case ID`, `Component`, `Priority` (`Highest`–`Lowest`), `Severity` (`Blocker`–`Trivial`), and reproduction steps.
2. **In Progress:** Assigned developer (`Backend MVC Team`, `Frontend View Team`, or `Database & QA Lead`) reproduces and fixes the defect inside strict MVC boundaries (`model/` or `controller/` or HTML View).
3. **In Review:** Fix is verified against `pytest -v` and the failed Test Case in `TESTING_DOCUMENT.md`.
4. **Done (Resolved / Verified):** Regression test passes and QA transitions issue status to `Done`.

### 3. In-App Jira Support & Cloud Sync
- **MVC Model (`model/entities.py`, `model/database.py`, `model/attendance_model.py`):** `JiraBugReport` entity and `Bug_Reports` SQLite table persist all Jira issue fields, issue keys (`SAS-1`, `SAS-2`, ...), and workflow transitions.
- **MVC Controller (`controller/attendance_controller.py`, `controller/http_controller.py`):** REST endpoints (`GET/POST /api/bugs`, `PUT /api/bugs/<id>/status`, `DELETE /api/bugs/<id>`, `GET /api/bugs/export-jira-csv`) push issues directly to **Jira Cloud REST API v3 (`/rest/api/3/issue`)** when `JIRA_BASE_URL`, `JIRA_EMAIL`, and `JIRA_API_TOKEN` are set, and export ready-to-import **Jira External System CSV** files (`SAS_Jira_Bug_Import.csv`).
- **MVC View (`admin.html`):** Built-in **Jira Bug Tracking & QA Defect Workflow** board lets QA log bugs linked directly to Test Case IDs (`TC01`–`TC40`) and transition workflow states in real time.
